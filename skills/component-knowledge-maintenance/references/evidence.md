# 存量与取证规则

## 1. 确认是首次整理还是更新

分别判断提交路由和盘点口径。currentVersionId 决定使用正式版草稿工具还是首次基线工具。盘点口径只看 MCP 成功返回的**后端原有实质内容**：已发布对象，或 `legacyContext` 中已有说明、规则、接口、适用关系、页面流程、交互与联动。只有组件/页面身份骨架、空名称/说明，属于首次；本次 meta 和模型推断不计存量。没有实质存量时形成有证据的全量候选，有实质存量时只提交相对存量的实质差异。未登记组件仍可存在共享存量，登记组件正文时复用已有共享对象。**两种模式都逐类检查**，缺证据不等于无内容；只有明确无内容才用 `[]`，未知用契约允许的 `null` 或保留旧值。

| 对象 | 从材料提炼什么 | 不得推断什么 |
| --- | --- | --- |
| COMPONENT | 名称、职责、接收、展示、行为、状态链；meta 与组件代码逐项核对 | 源码位置、装配关系不是业务正文；身份骨架应 UPDATE 而非重复 CREATE |
| PAGE / FLOW | 当前页面、明确登记的流程及用途 | 目录/路由不能证明业务流程 |
| KNOWLEDGE | 业务规则、指标口径、技术规则和明确需持久记录的冲突 | 代码可推导规则但不能冒充已确认业务要求；接口字段不复制成规则 |
| INTERFACE | 实际关联的用途、方法/地址、逐层请求/响应字段说明、错误、示例、规则 ID | 保留已登记字段 ID；新增字段先核实服务支持的标识生成规则，无依据时记录缺口；不猜含义、校验、示例；未知必填/可空不能猜；保留可验证的旧布尔值，无法确定时暂停该接口候选 |
| APPLICABILITY | 规则目标、适用条件、例外、明确替代 | 未知条件不等于无条件，当前组件变化不全局改写共享规则 |
| PAGE_FLOW | 显式页面-流程关系 | 不以父子装配推断 |
| INTERACTION | 动作、触发、提供内容、自身响应 | `response` 不是 HTTP 响应 |
| COMPONENT_RELATION | 显式交互目标、影响和条件 | 同用接口或共享知识不证明联动，也不推断传递影响 |

对每类形成盘点记录：`类型/稳定 ID 与版本/存量/meta 位置/代码位置/会话依据/结论/候选操作/缺口`。结论为新增、实质修改、关联调整、冲突、无变化、证据不足或不适用；“不适用”也须有依据。只查当前组件及明确关联接口/联动，不遍历无关模块。

## 2. 核对现有行为和需要更新的内容

从展示项、筛选和状态追到前端取值/计算/调用，再追到相关后端路由、业务处理和查询；逐项核实过滤、分组、分子分母、公式、时间边界、异常和缺省值。代码直接证明“当前实现如此”记 FACT；由实现提炼的业务意义、指标口径记 INFERENCE，并用 PENDING 候选等待审核。用户明确要求记 REQUIREMENT；只看到展示值、没看到计算来源时不补造公式。每条依据只给必要路径/位置与摘录，不上传整段会话、凭据或无关源码。

**指标口径。** 从直接展示的指标和公式引用的指标建立依赖清单，递归追溯到原始事实或已核实的共享口径。派生指标在候选正文中逐项写明公式、单位、精度和异常边界。每个基础指标逐项记录统计对象、数据来源、纳入和排除条件、时间窗口、分组维度、去重键及空值处理。即使基础指标仅出现在公式里，也要说明口径或引用已核实的共享口径。同名指标存在不同取数条件时分别写明适用范围。证据不足时列出对应指标和具体缺项，保留已核实内容。

例如，执行走势图的电访率 = 当日电访客户数 ÷ 当日推荐客户数 × 100%，四舍五入到两位小数，推荐客户数为零时返回空值。还需分别说明基础指标。推荐客户数取当日所选执行记录关联的最新成功方案结果，按非空推荐客户 ID 去重。电访客户数取同一执行链路、同一客户、执行日内的电访按钮点击，按推荐客户 ID 去重。接触客户数从符合条件的当日事件关联的接触明细取数，按接触明细客户 ID 去重。其余比率也按同一方式展开各自的基础指标。

**组件联动。** 同时追踪谁触发当前组件变化，以及当前组件会影响谁。沿上游接口找到消费组件，再核查源动作、回调或共享状态、目标响应和适用条件。记录这些环节的代码证据，并核实源交互和目标组件的正式 ID。登记或子树范围限制入稿时，照常记录已核实的链路和缺口。例如，筛选栏更新页面筛选状态，走势图监听该状态并重新取数。

联动关系的交互引用须能在同一候选预览清单解析。新增交互归属于动作发生的组件，已有入站关系保留实际源交互的身份。目标子树整理时，若需新增范围外源交互，记录链路并另行取得范围授权。可复用已登记交互时先核对正式版本及当前预览是否具备该引用。服务允许关系使用目标的正式 ID，首次登记时仅映射本次登记目标的临时键。

接口嵌套字段、错误和示例使用调用方提供的非空字符串 ID。版本化候选保留这些值，服务校验非空且不会为嵌套项分配 ID。保留既有 ID；新项优先用项目已有的稳定命名规则，无项目规则时可用 UUID 并在同一候选的复核与重试中保留。

逐对象判断存量。共享页面有说明、组件未登记、接口未登记时，分别复用页面、建立组件候选和梳理新增接口；组件正式版本仍单独决定提交工具。

按对象类型及稳定 ID 匹配，不能因标题相似合并；语义相同或仅措辞变化不提案。数值、条件、范围、例外、行为等实质变化才生成候选。冲突陈列双方事实，不擅自裁决；只有明确要求持久化冲突并有双方依据时创建 CONFLICT 知识。未提及的旧知识不删除，UNLINK 只解除当前组件关联，EXPIRE 需明确全局停用依据。共享对象新版只升级当前组件引用，不替其他组件升级。

每条 Change 具有唯一 `changeId`、操作、对象身份、`baseObjectVersionId/targetVersionId`、完整 `content`、`confirmationStatus`、证据及必要的 `atomicGroupId`。CREATE 使用 `new:` 临时键；新增规则及其适用关系同组接受，目标使用稳定的数据库对象 ID。未登记组件仅按下节约定使用服务返回的临时键。页面内组件 `meta.id` 只用于请求身份和 COMPONENT 正文中的 componentId。UPDATE 保留旧对象身份和未变字段；首次基线已有组件/页面骨架时用其旧 ID UPDATE。只有确认的代码事实与模型推断一起出现时，候选仍不得将推断标为 CONFIRMED。

逐个核对直接和上游接口。先完成契约盘点，输出已核实的字段树、类型、必填与可空、含义、校验、错误及可核实的示例，再独立判定能否入稿。未登记、字段 ID 规则未知或个别字段证据不足时，继续核实其余内容，按接口、方向、字段路径或提交条件记录缺口。当前组件未引用某接口或 MCP 返回 `INTERFACE_NOT_FOUND` 时，继续核查前端调用、后端路由、请求与响应 DTO、序列化和校验。按知识服务提供的接口身份生成候选：已返回登记对象的，契约有差异时以明确对象版本为基准提交完整 INTERFACE UPDATE，保留原有字段 ID；服务未返回登记对象的，按新增接口候选提交。接口唯一性由知识服务负责；服务返回已有对象身份或登记冲突时，以其结果重新核对并按契约处理。

以实际后端实现完整录入接口契约，覆盖用途、方法和地址、请求及响应的每层字段（含对象和数组子字段）、类型、`required`、`nullable`、`meaning`、必要的 `detail`、已证实的 `validation`、错误、可核实的示例及关联规则。文档与实现有差异时记录依据，契约采用实际后端行为。必需结构仍无法核实则列出接口、方向、字段路径及缺口。其他对象类型缺少登记时同样继续取证，按证据决定是否新增。
