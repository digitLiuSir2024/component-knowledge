# 通用前端组件元数据

## 目标与方案

统一使用 `data-component-id` 和 `data-component-name` 在组件源码中声明稳定 ID 和显示名称。项目提供扫描范围和输出路径。生成器可在不同项目运行，组件注册表只保存可复现的源码事实。职责、业务口径、交互和协作知识由组件知识技能根据源码和已有知识生成待审核草稿。

评估过统一源码标记和按项目配置标记两种方案。用户选择统一标记。统一方案减少项目间的规则差异，需要迁移 PlanReport 的源码和工作台选择器。可配置标记能兼容旧项目，但需要为生成器维护更多配置和校验逻辑。

## 生成与校验

- 第一版支持 PlanReport 使用的 JSX 和 TSX。标记提取与校验、输出各自独立，后续按实际接入需求支持其他源码格式，沿用相同的标记和注册表字段。扫描配置范围内的源码，用语法树读取同一 JSX 元素上的静态 ID 和名称。仅声明其中一项、空值、动态值或重复 ID 都报告文件及位置。显示名称可重复。
- 每条记录包含 ID、名称和仓库相对源码路径。生成器按 ID 稳定排序，输出 JSON 注册表。同样的输入生成相同的内容。校验命令比较生成内容与现有产物，发现缺失或过期时失败。
- 第一版字段范围为身份和源码定位。样式归属、装配树及运行时状态如有消费方需要，迁移时先核对其真实来源，再决定如何从源码确定性地保留。旧清单中的业务文本与报表专属协作推导退出通用产物。

## PlanReport 迁移

- 已登记可见区块改用统一标记并补充显式名称。保留已有组件 ID，保持工作台与已登记知识的关联。动态抽屉使用各具体区块的静态标记，移除外壳对业务区块 ID 的动态拼接。
- 工作台与组件知识技能改读生成后的注册表，以 ID 和源码路径定位组件。核对现有逻辑组件和页面级消费方后确定其迁移映射，避免清理旧清单时丢失定位能力。
## 组件知识技能迁移

- 技能通过新注册表的 ID、名称和源码路径定位组件，移除通过 `metaPath` 回读 `component.meta.ts` 的步骤。
- 技能核对组件源码、实际装配位置、会话说明和已有知识，生成职责、业务条件、展示口径、交互与协作关系的待审核候选。沿用现有提交审核流程和组件 ID，已有知识继续按原 ID 关联。
- 前端生成流程独立运行，产物仅随配置和被扫描源码变化。

## 验收

生成并核对 PlanReport 注册表，验证组件选择、名称展示、抽屉定位及现有知识关联。用独立的最小 JSX 或 TSX 项目验证复用和重复 ID 校验。对改动执行项目已配置的静态检查及必要编译。
